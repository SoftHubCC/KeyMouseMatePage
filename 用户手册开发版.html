1. 快速入门

启动程序

  • 打包版：双击 KeyMouseMate.exe。
  • 源码版：命令行运行 python run.py（或 python -m rpa，或双击 dev\run\app_run.bat）。
💡 开发版说明：自动迁移 程序启动时检测到旧版布局（userdata/config/config.json、userdata/config/passwords.db、userdata/floatbar/）会自动搬迁到新布局（见 第 18 章），旧文件保留 .bak 备份，无需手动操作。

第一个方案（5 步完成）

  1. 新建方案：菜单「方案 → 新建方案」，输入名称，保存。
  2. 新建节点：左侧「节点库」→「新建」，输入名称。
  3. 添加动作：弹出节点编辑器 →「添加动作」，选择「左键单击」，设置坐标，保存。
  4. 添加步骤：在主界面「方案步骤」面板 →「添加步骤」，选择刚创建的节点。
  5. 运行：点击「▶ 运行」按钮或按 Ctrl+Shift+S。
ℹ 节点可复用 节点是可复用的动作组，一个方案可以多次引用同一个节点。修改节点会同步更新所有引用它的方案。

2. 三层模型

程序以三层结构组织自动化任务：

方案（Plan） └─ 步骤列表（NodeStep） └─ 节点（Node） └─ 动作列表（Action）
层级文件位置说明
方案 Planuserdata/plans/<名>.json一次完整任务 = 步骤列表 + 监控规则 + 运行参数
节点 Nodeuserdata/nodes/<名>.json一组动作的具名单元，可被多个方案共享引用
动作 Action内嵌于节点最小执行单元，共 33 种类型

共享引用的意义

节点 = 可复用的动作组。例如「登录」节点被方案 A、B 共同引用，修改一次即全部更新。

  • 节点库面板显示每个节点的方案引用数。
  • 删除有引用的节点时会列出受影响方案并弹出确认。

公共模板与私有实例（快照）

动作与节点都有两种形态，界面上用徽标区分：

徽标形态存放位置改动影响
🔗公共实例关联动作库 / 节点库中的一份模板改模板 → 所有引用处自动同步
🔒私有实例内嵌在所属方案 / 节点文件里只影响这一处，不入库、不进分类树

快照（自包含）：公共实例在关联模板的同时，会把自己所用模板的全部字段副本一并存入方案文件。因此方案文件本身即完整可运行——单个 .json 直接分享给别人即可，接收方无需预先拥有相同的动作库 / 节点库。

  • 保存 / 改名模板 → 所有引用它的节点与方案快照自动刷新。
  • 删除模板 → 引用处自动降级为私有副本，方案仍可运行。
  • 编辑公共实例 → 每次都弹二次确认：修改模板＝全局生效（所有引用处一起变）、仅改这一份＝转为私有（只影响当前方案）、取消＝不改（默认聚焦取消，防误触）。
  • 新建默认私有：新增的动作 / 节点默认是私有实例；需要复用时点「转为公共」，填名称与分类后写入库，重名须改名（不会自动加后缀）。
  • 导入分享的方案：命中本地同 ID 的模板则保持公共并刷新快照，未命中的自动降级为私有副本，导入后即可直接运行。

计划级参数

  • 启动延迟：方案启动后等待若干秒再执行第一步。
  • 动作默认间隔：每个动作执行后的等待时间（动作自身的"后置等待"可覆盖）。
  • 默认方案：下次启动自动加载的方案（存于 userdata/data.json）。

3.5 典型场景示例

示例一：自动登录网页

方案「自动登录」：
  步骤1「打开网站」(1轮)
    节点「登录-打开网页」
      ├─ action: open_website → https://example.com/login
      └─ action: wait → 3s
  步骤2「输入凭证并登录」(1轮)
    节点「登录-填表单」
      ├─ action: ocr_check → 关键词"用户名", 区域追踪
      ├─ action: tab_click → 点击用户名输入框
      ├─ action: input_text → 用户名文本（可用 {变量.用户名}）
      ├─ action: tab_click → 点击密码输入框
      ├─ action: input_text → 从密码库取密文
      └─ action: left_click → 坐标点击[登录]按钮

示例二：批量表单提交 + 弹窗处理

方案「批量提交」：
  步骤1「循环提交」(100轮)
    节点「提交操作」
      ├─ action: wait → 0.5s
      ├─ action: ocr_check → 关键词"提交按钮", 点击
      ├─ action: wait → 1s
      └─ action: goto → 回到本节点第1步
  监控规则1「错误弹窗处理」：错误,报错,异常 → 节点「处理-报错弹窗」
  监控规则2「确认弹窗」：确认,确定,是否继续 → 节点「处理-确认弹窗」

示例三：定时巡检报表

方案「每日巡检」：
  步骤1「启动巡检」：open_file → D:\scripts\inspection.py
  步骤2「等待结果」：wait_text → "完成"或"error"，超时300s
  监控规则「意外弹窗」：异常,崩溃,退出 → 节点「处理-异常」
定时调度：Cron 0 0 9 * * 1-5 *（工作日 9:00:00）→ 每日巡检

4.7 新增动作详解与典型场景

下面对近期新增的 13 种动作（动作总数已达 33 种）展开说明主要用法与应用场景，参数速查见上文 4.1～4.6 各表。

动作怎么用典型场景
▍点击 + 输入组合
单击后输入填坐标定位 + 输入内容：先单击该坐标获得焦点，再粘贴文本；执行次数 = 重复点选输入几遍表单逐项填写（点用户名框输入账号、点密码框输入密码），一个动作顶替「单击 + 输入文本」两步
单击后输入完Tab同「单击后输入」，输入完成后自动再按一次 Tab 跳到下一控件连续表单一条链填完——"输完账号按 Tab 到密码框"，省去为每个输入框单独算坐标
双击后输入双击坐标后粘贴文本需双击才进入编辑状态的控件：Excel/表格单元格、文件重命名框、双击展开树节点；双击也可用于选中一段词后覆盖输入
双击后输入完Tab同「双击后输入」，输完自动按 Tab表格类软件中"双击单元格 → 输入 → Tab 到下一格"的连续录入
▍鼠标增强与数据采集
滚轮滚动坐标定位 + 方向(up/down) + 滚动格数：先把鼠标移到该位置，再滚动 N 格长页面翻页浏览、下拉列表选第 N 项、滚动触发列表懒加载；比按键 PageDown 粒度更细
复制选区到变量可选填坐标（填了先点一下聚焦），然后 Ctrl+C 复制当前选区，读剪贴板存入指定变量；之后其它动作用 {变量.名} 引用从网页/软件抓当前选中内容：复制订单号、报错信息、价格，供打开网址、写文件、条件判断使用。注意 Ctrl+C 复制的是"当前已选中"的内容，目标处需先有选区
▍窗口管理
激活窗口填窗口标题关键词（逗号分隔多个，任一包含即命中），把匹配窗口带到前台；未命中可跳转多软件协作流程的第一步（先激活"记事本"再写入）；运行前确认目标程序已打开，没开走失败分支
等待窗口标题关键词 + 超时秒数轮询等待，窗口出现即激活，超时走未命中跳转等"导出完成"弹窗、等软件启动后的主窗口、等登录成功页；"出现才继续、超时走失败"比盲等固定秒数可靠
▍图像识别
找图点击截一小块目标图作模板，在区域内模板匹配（阈值 0.8），命中点击中心+偏移控件位置会漂移的界面（按钮今天在 (800,300) 明天在 (795,310)，坐标点击会失效）；也适合无文字的图标/按钮，按"长什么样"定位而非坐标
等待图片模板图片 + 超时轮询，图像出现即继续（只等不点），超时走跳转等加载圈消失、等"下载完成"图标出现、等进度条走完；适用于弹窗无标题或内容型提示的场景
▍OCR 增强与流程辅助
OCR偏移双击识别关键词后，在命中位置加偏移做双击双击打开识别到的条目：文件列表双击文件名、聊天记录双击联系人、表格双击某行进入编辑；与 OCR偏移点击/OCR偏移点击输入 配成三件套
随机延迟填基准时长（秒），实际在基准值的 50%~150% 间随机等待批量提交时每步间随机停顿，让操作节奏更拟人；也适用于等响应时间不确定的页面
写文件目标文件路径 + 写入内容（支持 {变量} 模板），追加一行并自动加时间戳前缀运行结果留痕：把复制到的订单号、OCR 识别结果逐轮追加到 txt/csv；配合「复制选区到变量」组成"抓取 → 落盘"流水线

组合示例：自动取数流水线——一条流程串起多个新动作：

步骤动作配置要点作用
1激活窗口关键词：业务系统确保目标程序在前台
2等待图片加载圈消失模板，超时 30 秒等页面加载完

5. 执行次数

所有动作类型均支持执行次数（loop_count），默认 1 次。

设置位置

  • 节点编辑器 → 编辑动作 → "执行次数" 字段
  • 动作管理器（全局库）→ 编辑 → "执行次数" 字段
  • 动作列表表格中均有"执行次数"列，支持右键「列设置」隐藏或调整宽度

行为

  • 动作执行 N 次后，继续下一个动作；每次之间自动等待"后置等待"时间。
  • 例：动作 A 执行次数=2，动作 B 执行次数=1 → 顺序为 A→A→B。

6. 条件分支与工作流

6.1 步骤级条件

条件类型说明
无条件始终执行（默认）
变量表达式表达式为 true 时执行
OCR 区域识别指定区域 OCR，命中关键词时执行
OCR 数值比较识别区域第一个数字，与阈值比较

条件不满足时：跳过（默认）/ 跳转到步骤 #N / 终止方案。

6.2 动作出错处理

策略说明
继续记录日志，执行下一个动作（默认）
重试 N 次失败后重试，仍失败则按策略处理
跳转到步骤 #N跳到指定步骤
中止方案停止整个方案

6.3 动作级跳转（节点内）

  • 命中→跳转：OCR 命中后跳到节点内第 N 个动作
  • 未命中→跳转：OCR 未命中后跳到第 N 个动作
  • 可组合形成节点内循环

7. 变量与表达式

7.1 内置变量

变量含义
{轮次}当前节点循环第几轮（1 基）
{步序}当前步骤序号（1 基）
{节点名}当前步骤引用的节点名
{方案名}当前方案名称
{ocr.last}最近一次 OCR 全文
{ocr.hit}最近一次 OCR 是否命中

7.2 表达式语法

表达式用于步骤执行条件，不使用 eval，安全受限。

运算符：== != > < >= <= contains matches startswith endswith and or not；支持括号分组。

matches 支持正则：右侧用 re: 前缀。

{变量.已登录} == true
{ocr.last} contains '成功'
{轮次} > 3 and {变量.停止} != true
{ocr.last} matches 're:订单号:\s*\w+'

7.3 模板替换

在「输入文本」「按键」「打开文件」「设置变量」的值中可写 {变量名}，执行时自动替换；未知变量原样保留，不报错。

8. OCR 识别

8.1 双引擎体系

引擎依赖特点
RapidOCR（默认）rapidocr-onnxruntime（已装）PP-OCR 模型，中文准确率高，体积小
PaddleOCR（可选）pip install paddlepaddle paddleocr上限略高，不支持 Win7

auto 模式：按 RapidOCR → PaddleOCR 自动回退。

8.2 OCR 设置

菜单「工具 → OCR 设置」：引擎切换 / 置信度阈值（0.0~1.0）/ 调试日志 / 区域测试。

8.3 小区域放大

识别区域过小时（< 200px 宽或高），自动放大 1.5~2 倍再识别。

9. 监控规则（弹窗处理）

9.1 工作原理

主流程：步骤1 → 动作A → 动作B → 动作C → ... ↑ 监控线程在每个动作之间检查点触发 命中关键词 → 执行处理节点 → 回到打断处继续（不重跑方案）

9.2 创建监控规则

菜单「工具 → 监控规则」→ 新建：

参数说明
区域OCR 监控的屏幕区域（可用追踪取区域）
关键词逗号分隔，支持 re: 正则前缀
检测间隔默认 1.0 秒
冷却时间触发后多少秒内不重复触发
处理类型执行节点 或 终止方案
处理节点命中后执行的节点名

9.3 调试技巧

  1. 打开「OCR 调试日志」，查看 🔍 [规则名] OCR: ... 识别内容
  2. 添加 ocr_check 动作存变量并截图，确认区域是否正确
  3. 触发过于频繁时增大冷却时间

10. 定时调度（Cron）

10.1 创建调度

菜单「工具 → 定时调度」→ 新建。调度包含：Cron 表达式（7 字段：秒 分 时 日 月 周 年）、启动延迟、关联方案、调度名称。

10.2 Cron 表达式速查

字段示例含义
秒0每分钟的第 0 秒
分*/5每 5 分钟
时9-189点到18点
日L每月最后一天
周1-5周一到周五

10.3 高级语法

语法示例含义
,0,30 * * * *每小时的第 0 和 30 秒
L0 0 L * *每月最后一天 0 时 0 分
W0 0 15W * *每月最接近 15 号的工作日
NwD0 0 15NwD * *每月第 15 个工作日
#N0 0 * * 6#2每月第二个周六

10.4 运行状态

  • 调度器精确等待下次触发时刻（非轮询），到达自动运行关联方案。
  • 编辑时右侧显示未来 12~48 个触发时间预览。
  • 主窗口关闭后调度继续运行（托盘模式下）。

14.1 新建

14.2 复制规则

复制对象新 ID复制行为

14.3 重命名与删除

  • 节点重命名：自动同步所有引用它的方案步骤（按 ID 与名称双匹配）及监控规则引用。
  • 动作重命名：旧文件自动删除，新名称文件写入。
  • 删除：被引用的对象会列出受影响者并要求确认；方案删除不影响节点和动作文件。

14.4 列设置

所有表格支持右键 →「列设置…」：显示/隐藏列、拖拽调整列宽，自动保存。

16. 实时可视化（键鼠可视化）

由独立工具 KeyMouseViz 有机融合而来的内置模块（rpa/viz.py），随主程序启动常驻、随主程序退出关闭，无需管理员权限，支持高 DPI / 多显示器。

18.1 旧版自动迁移

  • userdata/config/config.json → config/config.json（旧文件保留 .bak）
  • userdata/config/passwords.db → userdata/passwords.db
  • userdata/floatbar/ → config/floatbar/
  • config.json 中 plan_order / node_order / default_plan → userdata/data.json

18.2 备份与迁移

  • 完整备份：同时复制 config/ 与 userdata/。
  • 只备数据：复制 userdata/（方案/节点/动作/密码/排序全部在内）。

18.3 二维码

「帮助 → 关于」按顺序查找：config/qrcode.png → EXE 同目录 → 程序目录。放入 config/qrcode.png 即可显示；打包时若项目根目录存在 qrcode.png 会自动打入 config/。

19. 迁移旧方案

菜单「方案 → 迁移旧方案」：扫描旧版 schemes/*.json，自动转换：

  • 主任务 → 节点「主流程-方案名」
  • 弹窗规则 → 监控规则 + 处理节点「弹窗处理-方案名-规则名」
  • 子动作、点击坐标、密码引用全部保留；旧版"总轮次" → 步骤循环次数

幂等：已存在的同名内容自动跳过，可重复执行。
